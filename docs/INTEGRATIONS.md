# Integraciones opcionales

## Firebase Auth/Firestore
Registra `es.planidroid.app`, añade SHA-1 y SHA-256 del certificado de debug o release, habilita Google, descarga `app/google-services.json`. No incluyas claves de cuenta de servicio en el proyecto Android. Ejecuta las pruebas de emulador antes de publicar reglas. Firestore: `/users/{uid}/records/{id}` privado; `/sharedSpaces/{id}` espacio compartido, `/memberships/{spaceId}~{email}` invitación o membresía; `/sharedSpaces/{id}/comments/{id}` comentarios. Los cambios compartidos usan versión transaccional y lectura de servidor, no caché privada local. Spark puede ser suficiente para uso reducido; revisar cuotas vigentes de consola. Storage cerrado.

## Calendar
Habilitar Google Calendar API en Google Cloud. Configurar pantalla de consentimiento OAuth y usuarios de prueba; cliente Android con package y SHA-1. La app usa AuthorizationClient de Google Identity Services para solicitar `https://www.googleapis.com/auth/calendar.events` después de autenticar por Google; usa la cuenta de Firebase explícita. El token se recibe en memoria, no se incluye en backups ni en Firestore. Manual: seleccionar sesiones que exportar; las ya enlazadas se reconcilian siempre. Automático: WorkManager cada 30 min, sujeto al sistema y a que Google otorgue un token sin interacción. El usuario puede desactivar el modo. Las fechas importadas son del calendario principal de −30 a +366 días. Los externos no se editan; las sesiones propias se actualizan con identificador `p` + UUID sin guiones, private property y ETag. La comparación de base/local/remoto evita overwrites concurrentes; si se borra en Google o hay cambios divergentes, se notifica y preserva la sesión local. No hay reconciliación de borrados remotos interactiva ni selector de calendarios secundarios. Los eventos externos se cachean localmente por cuenta y bloquean la agenda. El apagado limpia esa caché, no borra eventos de Google ni revoca consentimiento de la cuenta; revocar desde permisos de Google.

## Gemini
No introducir API keys en APK. `backend/src/main/kotlin/es/planidroid/backend/Server.kt` implementa POST `/ai`. Requiere JDK 17, Gradle 8.9 y Firebase Admin con ADC del mismo proyecto, `GEMINI_API_KEY`, `GEMINI_MODEL` (modelo habilitado en tu proyecto), `PLANIDROID_ALLOWED_UIDS` (separados por coma), `PORT` opcional. `gradle -p backend test` y `gradle -p backend run` desde la raíz. Desplegar detrás de HTTPS en infraestructura propia con límites de peticiones/tamaño adicionales; usar secretos del proveedor. El proxy verifica token Firebase con revocación, allowlist, 30 llamadas por ventana móvil de una hora por UID y proceso; el límite no es distribuido ni un control de gasto garantizado. Añade cuotas del proveedor y alertas. No registra payload deliberadamente. No usar una URL de terceros: recibe un token Firebase y el texto consentido. La IA no escribe en la base: devuelve propuesta validada, usuario confirma. En Ajustes, selecciona Gemini y pon la URL completa `https://.../ai`. Local funciona sin proxy. No se implementa todavía Gemini multimodal para alimentos: ML Kit es el reconocimiento local disponible.

Referencias: https://developer.android.com/identity/authorization · https://developers.google.com/android/reference/com/google/android/gms/auth/api/identity/AuthorizationRequest.Builder · https://developers.google.com/workspace/calendar/api/v3/reference/events · https://developers.google.com/workspace/calendar/api/guides/version-resources · https://firebase.google.com/docs/firestore/security/rules-fields · https://firebase.google.com/docs/firestore/security/rules-query .

## Aprobación manual y consumo reducido
Antes de habilitar sincronización real, validar reglas en el emulador. En Firebase Console > Authentication > Users, copiar el UID del usuario. En Firestore crear la colección `approvedUsers` y un documento cuyo ID sea exactamente ese UID, con el campo booleano `enabled: true`. Repetir para cada cuenta, incluida la del propietario. Para revocar, cambiar enabled a false o eliminar el documento. Los clientes no pueden crear ni modificar estas autorizaciones, ni listar la colección. El inicio de sesión no concede acceso a datos. El usuario sin aprobación solo puede leer su propio documento de autorización al solicitar una comprobación; las consultas de reglas pueden consumir lecturas aun cuando se deniega una petición. No es un límite absoluto contra abuso; usar App Check y vigilar las cuotas.
Sincronización privada manual por defecto, opcional cada seis horas; los trabajadores antiguos se cancelan/actualizan. Solo se suben registros modificados y se descargan cambios desde el último timestamp de servidor procesado (límite inclusivo). Las listas compartidas se consultan con Actualizar y tras acciones explícitas. Calendar automático pasa a seis horas al volver a configurar su modo. Gemini exige aprobación en el cliente y sigue sujeto a la allowlist independiente del servidor. Sin fotos en Firestore. No habilitar Storage. La autorización no elimina datos previos del dispositivo.

## Registro automático de solicitudes (0.1.1.3)
En el inicio de sesión y al pulsar comprobar acceso, se consulta el documento propio en una transacción. Si no existe, se crea con `enabled: false`, `email` verificado de Google y `createdAt` de servidor. Si existe, se conserva intacto, incluso si el administrador solo creó el campo enabled. Las reglas permiten únicamente crear el documento propio pendiente con los tres campos exactos; no permiten modificarlo, borrarlo ni listar aprobaciones. Los trabajadores de fondo no crean solicitudes. Para revocar conservar el documento con enabled false. No hay listeners ni sondeo automático de aprobación. La creación consume una escritura y la comprobación al menos una lectura. Publicar las reglas de este PR en Firestore (base de datos default), no solo fusionar en GitHub. Mantener Spark y no usar reglas abiertas para depurar.

## Cuenta simplificada y Gemini único (0.1.1.4)
Ajustes muestra cuenta, aprobación en vivo (listener de un documento solo mientras la pantalla está activa), cerrar sesión y estados de Google, Firestore, Calendar y Gemini. Las acciones se abren al pulsar el servicio. Calendar y Gemini muestran el último éxito comprobado (no implica disponibilidad permanente); Gemini se prueba únicamente bajo demanda con una petición mínima. Herramientas en Espacios conserva copias, apariencia y notificaciones. No hay proveedor de IA local seleccionable ni fallback automático; la edición manual y el cálculo de horarios no requieren IA.
Gemini requiere el backend existente, ahora con verificación de approvedUsers/{uid}.enabled en servidor en cada petición y allowlist adicional opcional. Firebase AI Logic authenticated-users mode no impone una allowlist por UID, por lo que no se usa acceso directo que permita consumir cuota antes de la aprobación. Configurar en el Gradle de usuario (fuera del repositorio) la propiedad planidroidGeminiEndpoint=https://TU-SERVIDOR/ai; recompilar. Es una URL pública de servicio, no una clave. El servidor necesita ADC y GEMINI_API_KEY/GEMINI_MODEL; no habilitar Blaze automáticamente. No enviar claves al APK. No hay endpoint desplegado todavía.
Calendar comprueba los scopes concedidos, muestra código OAuth o motivo HTTP y permite conectar desde OFF sin pasos previos. El modo manual selecciona sesiones; la autorización no garantiza que cada escritura tenga éxito.

## 0.1.1.5: cuenta obligatoria, trabajo sin conexión y Gemini personal
Primera autorización en línea por UID, posterior acceso local solo a la misma cuenta previamente aprobada en esta instalación. Una respuesta de servidor con false bloquea el acceso y cancela sincronización; sin red se conserva la última autorización confirmada. No se puede detectar una revocación hasta recuperar conexión. El listener de un documento vive mientras la UI está activa. No se migran datos invitados sin acción explícita en Herramientas.
Room conserva cambios/tombstones antes de sincronizar; WorkManager encola un trabajo con red y retraso de un minuto para agrupar cambios y otro periódico cada seis horas. Los conflictos no sobrescriben cambios locales. Las fotos y documentos siguen locales. Gemini no es obligatorio; cada cuenta/dispositivo introduce su propia API key (AES-GCM en Android Keystore, ciphertext en noBackupFilesDir, sin Room, Firestore, exportación ni logs). Se elimina al cerrar sesión. Se manda solo como cabecera HTTPS a generativelanguage.googleapis.com, sin redirecciones ni servidor propio. El coste corresponde al proyecto de cada usuario; respetar términos de Google, especialmente uso de servicios de pago para clientes distribuidos en EEE. No garantizar coste cero; nunca habilitar facturación automáticamente. Gemini es opcional en captura, sugerencias de recetas y OCR de imágenes; OCR ML Kit y edición manual permanecen disponibles. Las operaciones de IA requieren autorización actual del servidor y confirmación de los datos enviados.

Shared content: known lists/homes are cached by UID in app-private storage. Edits to existing shared spaces are queued with the base version and revision; on reconnect a Firestore transaction rejects concurrent changes rather than overwriting. Pending conflicts can be inspected and discarded in Tools; invitations, creating shared spaces, publishing and membership management require a connection. Shared comments are not queued. New private objects can be created offline. Cached shared data may be stale until refresh, and permission changes are rechecked by Firestore.
